# QQ 适配器接入

麦麦绘图使用 MaiBot SDK 的标准聊天消息和发送能力，无需在插件中填写适配器地址或选择 QQ 后端。

| 适配器 | 身份与会话 | 图片输入 | 结果发送 |
| --- | --- | --- | --- |
| [QQ 官方机器人适配器](https://github.com/Mai-with-u/MaiBot-QQ-Adapter) | `qq` 平台，使用 Host 提供的真实会话；支持 OpenID 与适配器绑定后的群号/用户号 | 同条消息的真实图片附件 | 通过 SDK 发送图片，由适配器上传 QQ 富媒体 |
| [统一 QQ 适配器](https://github.com/Mai-with-u/MaiBot-SnowLuma-Adapter) | `qq` 平台，由适配器识别 SnowLuma 或 NapCat | 同条消息图片；引用消息在当前会话可查询或有缓存时恢复真实图片 | 通过 SDK 发送图片，由适配器处理客户端动作差异 |

## 使用与限制

- **官方身份**：OpenID 与 QQ 数字号不同，不需要改成数字。适配器若配置统一账号或绑定 ID，绘图沿用 Host 的会话与身份，插件不自行计算 session_id。多个 QQ 账号共存时，API 回传必须指定完整真实会话 ID。
- **直接图生图**：将真实图片与 `/绘图 图生图 描述` 一起发送。适配器下载失败时可能仅剩 `[图片]` 文本；插件会要求补图，不把描述当成图片，也不会降级文生图。
- **引用图片**：统一适配器会输出标准 reply 目标 ID，插件限定在当前会话查询原图。官方适配器当前源码没有把 QQ 引用目标转成标准 reply 段，无法保证引用图片可用；此时请直接附图。历史图片已清理、进程重启导致缓存丢失时也可能需要重新发送。
- **原图 URL**：两种适配器当前都会输出 Base64 图片，但没有在标准图片段保留原始 HTTP(S) URL。支持 Base64 的模型正常处理；百炼可灵/Vidu 等要求原图 URL 的模型会明确拒绝此类源图，不生成虚假地址，也不将用户图片额外上传到第三方图床。
- **官方发送限制**：官方 QQ 按消息类型拆分发送，被动回复有时效与次数限制；群聊一条入站消息的被动回复最多 5 次，状态提示和每张图片都会占用发送次数。超出被动窗口时是否可主动发送取决于 QQ 平台额度，插件不能保证绕过此限制。
- **发送未确认**：SnowLuma 会核对真实群消息序号；本地受理或未确认投递不等于发送成功。SDK 返回失败、超时或异常时，插件保留已确认数量和未确认状态，不换会话自动重发；先核对聊天记录和任务结果，避免重复图片。
